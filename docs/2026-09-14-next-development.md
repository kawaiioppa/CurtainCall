# CurtainCall 앞으로 할 일

작성일: 2026-09-14  
기준 커밋: `fceee19` (`feat: connect room membership management flow`)

이 문서는 현재 구현 상태를 기준으로 다음 개발 순서와 완료 조건을 정리한 로드맵입니다. 화면 디자인 개선은 핵심 로직과 최소 사용자 흐름을 검증한 뒤 진행합니다.

## 현재 완료된 범위

- 이메일 가입·로그인·이메일 인증·비밀번호 재설정
- 공연 목록 검색, 지역·날짜 필터, 페이지 조회, 공연 상세와 회차 선택
- 회차별 방 목록과 방 생성·입장
- 방 상세, 참여자 목록, 내 참여 방 목록
- 방장 위임, 참여자 강퇴, 방 퇴장, 방 정보 수정
- 방 정원·만료·강퇴 재입장·성인 전용 규칙의 서버 측 검사
- Swift portable 테스트 28개
- PostgreSQL 롤백 테스트와 마지막 한 자리 동시 입장 테스트

## 1. 메시지 저장과 권한

### 할 일

- `messages` 테이블 추가
- 방별 증가 순번과 클라이언트 생성 idempotency UUID 저장
- 참여 중인 사용자만 메시지를 조회·전송할 수 있는 RLS와 RPC 추가
- 메시지 이력 cursor pagination 구현
- 퇴장·강퇴·방 만료 후 메시지 조회 차단

### 완료 조건

- 같은 UUID로 재전송해도 메시지가 한 번만 저장된다.
- 두 사용자가 같은 방에서 보낸 메시지를 순서대로 조회할 수 있다.
- 참여하지 않은 사용자와 접근이 취소된 사용자는 이력을 조회할 수 없다.
- 정렬과 권한 규칙을 SQL 테스트로 검증한다.

## 2. 최소 채팅 화면

### 할 일

- `CurtainCall/Chat/`에 모델·서비스·스토어·화면 추가
- 방 상세에서 채팅 화면으로 이동
- 로딩, 빈 이력, 전송 중, 실패, 재시도 상태 표시
- 실패한 메시지는 원래 UUID로 재전송
- 앱을 다시 열었을 때 저장된 이력 복원

### 완료 조건

- 방에 입장한 사용자가 메시지를 작성하고 저장된 결과를 볼 수 있다.
- 네트워크 실패 시 입력 내용이 사라지지 않고 재시도할 수 있다.
- 화면을 다시 열어도 서버에 저장된 메시지가 보인다.

## 3. 실시간 수신과 재연결

### 할 일

- Supabase Realtime 채널 연결
- 이벤트에는 메시지 본문을 싣지 않고 변경 알림만 사용
- 알림 수신 후 권한 있는 메시지를 다시 조회
- 마지막 sequence 이후 누락 메시지 복구
- 백그라운드·포그라운드 전환과 연결 해제 시 구독 정리
- 퇴장·강퇴·만료 시 채널 해제 및 화면 접근 차단

### 완료 조건

- 두 기기에서 새 메시지가 갱신된다.
- 연결이 끊겼다가 복구되면 누락된 메시지가 순서대로 보인다.
- 접근 권한이 사라진 사용자는 이후 알림으로 메시지 본문을 받지 않는다.
- 재연결·누락 복구·권한 취소를 통합 테스트한다.

## 4. 실제 공연 데이터 운영

### 할 일

- 서버 측 KOPIS XML 수집기 구현
- API 키를 iOS 앱에 넣지 않고 서버 비밀로 관리
- 공연과 회차를 idempotent upsert
- 외부 API 실패 시 기존 저장 데이터 유지
- 운영자가 시작·종료 시각과 출처를 명시해 회차를 등록하는 절차 추가
- 실제 자격 증명이 준비되면 수집과 앱 조회를 연결

### 완료 조건

- 같은 KOPIS 데이터를 여러 번 수집해도 중복 공연·회차가 생기지 않는다.
- 일부 필드가 없는 응답도 안전하게 처리한다.
- 외부 수집 실패가 기존 카탈로그를 삭제하지 않는다.
- 확인되지 않은 회차 시간을 추정하지 않는다.

## 5. 출시 전 검증과 디자인 개선

### 할 일

- macOS/Xcode에서 앱 빌드와 iOS 시뮬레이터 테스트 실행
- 두 인증 사용자의 탐색 → 방 생성 → 입장 → 채팅 흐름 검증
- 신고·차단·계정 관리 등 운영에 필요한 기능 점검
- Design skill을 활용해 화면 구조, 색상, 타이포그래피와 공통 컴포넌트 재설계
- 디자인 변경 후 UI 회귀 테스트 갱신
- README와 진행 문서에 실제 검증 결과와 남은 외부 의존성 기록

### 완료 조건

- Xcode 테스트와 핵심 UI 흐름을 실제 Apple 환경에서 확인한다.
- 운영 기능과 계정 상태 변화가 사용자에게 명확하게 표시된다.
- 디자인 변경이 메시지 저장·권한·재연결 동작을 깨뜨리지 않는다.
- KOPIS 자격 증명이나 배포 권한처럼 외부에서 필요한 항목은 별도로 기록한다.
